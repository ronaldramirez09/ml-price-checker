**Automatización de comisión real (ago-2026) — cómo funciona:**

El botón "🔎 Sugerir comisión real (según categoría)" en el formulario:
1. Llama a `costos-mercadolibre` (`accion: "categorias"`) con el nombre del producto → usa `/sites/{site}/domain_discovery/search`, público, SIN necesitar token, devuelve categorías candidatas (ej. "Barras de Sujeción", "Sellos"...). Puede no acertar la categoría exacta que el vendedor eligió (varias categorías son plausibles para un mismo nombre) — por eso se muestran varias opciones, no una sola.
2. Para cada candidata, llama a `costos-mercadolibre` (`accion: "comision"`) con `category_id` + el precio de venta ya ingresado → usa `/sites/{site}/listing_prices?price&category_id` CON el `access_token` de la cuenta "Mercatodo" (esto si requiere token — sin token da 403 PolicyAgent, igual que el buscador viejo).
3. Se muestran botones "Categoría (nombre completo) — Clásica/Premium X% ($monto)" — al tocar uno, precarga ese % en el campo de comisión (que sigue editable a mano).

Backend: `supabase/functions/costos-mercadolibre/index.ts` — función pública (`verify_jwt = false` en `config.toml`, la calculadora es una página estática sin login). Expone SOLO estas 2 acciones acotadas (no es un proxy genérico a la API de ML, eso sería un riesgo de seguridad dejado público). Reusa `_shared/mercadolibreAuth.ts` (mismo helper que `buscar-en-mercadolibre`) para el `access_token` de la cuenta ML — refresca solo si está vencido.

**Envío: NO se automatizó — investigado a fondo y descartado (ago-2026):**
- `/items/{id}/shipping_options?zip_code=X` SÍ responde (no da el 403 de siempre, a diferencia del buscador) — pero exige un `zip_code` de destino válido, y Chile en MercadoLibre no usa código postal como dato principal: la cuenta "Mercatodo" no tiene ninguno registrado (`/users/me` → `zip_code: null`), y los envíos reales (`/shipments/{id}`) muestran un ID de ciudad interno de ML en la mayoría de los casos, no un zip.
- Se probó igual con un código postal real tomado de un envío real que sí lo tenía poblado (4121746) contra dos ítems activos distintos (uno con dimensiones/peso ya cargados: 59×9×15cm, 212g) — ambos casos siguen dando `400 invalid_zip_code / zip code not found`. No es un problema de faltar peso/dimensiones.
- Endpoints alternativos probados y con 404 (no existen o no son así): `/sites/{site}/shipping_options/free`, `/items/{id}/shipping_options/free`.
- Sí se puede leer el costo de envío REAL de una venta ya concretada (`/shipments/{id}` → `base_cost`, `shipping_option.cost`, `shipping_option.list_cost`) — útil como referencia histórica ("la última vez que vendiste algo así, el envío costó X"), pero no sirve para predecir el costo de una venta que todavía no pasó. No implementado (no es lo que pedía el usuario).
- Conclusión: costo de envío queda manual a propósito. No reintentar sin que MercadoLibre exponga alguna otra vía para Chile específicamente.
